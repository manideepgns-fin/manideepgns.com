# Posts

One post a week about the work, on X (@Manideep_GNS) and LinkedIn. A cloud routine drafts; Manideep posts. Nothing here is published by a machine.

## How it works
- `backlog.md`: ideas, one per line, in rough order. Each line is a topic plus where the facts live in this repo.
- `log.md`: what has been drafted and posted, newest first. A topic in the log is done; don't draft it again.
- `drafts/YYYY-MM-DD-slug.md`: the drafts the routine wrote, one file per week. The PR that adds the file is the review.

## Voice
- Plain words, short sentences, one idea per post. Casual, a little playful, never loud.
- Evidence, not claims. Show the thing (a number from the site, a decision, a line of code, a mistake) and let the reader conclude. Never write "finance guy who builds" or "finance engineer" as a label for himself; the work says it.
- Say what went wrong when it did. The mistakes are the best posts.
- No em dashes. No hype words (passionate, leverage, excited, game-changer, journey). No emoji. No hashtags. No "thread 🧵".
- Facts come only from this repo: `index.html`, `writing/`, `wrapped/`, `stack.html`. Nothing about UrbanPiper's revenue, customers, headcount, or internal numbers. If a fact isn't on the site, it doesn't go in the post.
- Link to the site when the post points at something on it. On X use a fresh query string each week (`https://manideepgns.com/?p=YYYYMMDD`) because X caches link cards per exact URL. On LinkedIn use the plain URL.

## Lengths
- X: up to about 600 characters (Premium allows long posts, but short still wins).
- LinkedIn: 600 to 1,300 characters, line breaks between ideas, the link on its own last line.
